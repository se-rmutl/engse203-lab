## 4. ตรวจ M1 และ M2 (ไม่มีคาบ — ตรวจจาก GitHub)

```bash
# ครั้งเดียว: clone ทุกทีมไว้ในโฟลเดอร์เดียว
mkdir -p ~/ftp/sec1 && cd ~/ftp/sec1
while read url; do git clone -q "$url"; done < sec1-repos.txt

# ทุกครั้งที่ตรวจ
for d in */; do
  ( cd "$d" && git pull -q && git fetch -q --tags
    npm install --prefix api --silent && npm install --prefix frontend --silent
    node --disable-warning=ExperimentalWarning check-project.mjs --skip-build --json "../${d%/}.json" > "../${d%/}.txt" 2>&1 )
done
grep -h "รวม ผ่าน" *.txt
```

> ⚠ `check-project.mjs` เป็นไฟล์ของทีม (อยู่ใน repo ทีม) — ทีมอาจแก้ให้ผ่านง่ายขึ้น · ตอนตรวจจริงให้**คัดลอกตัวจาก Course Repository ทับก่อนรัน**:
> `cp ~/engse203-lab/labs/final-term-project/kit/check-project.mjs "$d/"`

| ขั้น | ต้องเห็น | ถ้าไม่เห็น |
|---|---|---|
| M1 | repo มีอยู่ · มีผู้สอนเป็น collaborator · tag `v0.1.0` · `TEAM_CONTRACT.md` · `project.config.json` (T1 ผ่าน) · `schema.sql` มี 2 ตารางของหัวข้อ (B1) · มี Issues | ส่งข้อความเตือนทีม · ไม่มี repo = เรียกคุยภายใน 1 วัน |
| M2 | tag `v0.5.0` · B2.* ผ่านเกือบหมด · F1 (หน้า login) · มีการ deploy ครั้งแรก · ทุกคนมี commit | ทีมที่ B2 ผ่าน < 5 ข้อ หรือมีสมาชิกไม่มี commit → นัดคุยออนไลน์ 10 นาที |

**สัญญาณอันตรายที่ต้องดูตอน M2**

- สมาชิกคนหนึ่งไม่มี commit เลย → ถามทั้งทีม · ถ้ายืนยันว่าหาย ให้ทีมเขียนใน `TEAM_CONTRACT.md` แล้วผู้สอนตัดสิน (แยกให้ทำคนเดียวได้ แต่ขอบเขตลดลง)
- ยังเป็นตาราง `requests` (B1 ไม่ผ่าน) → ทีมยังไม่ได้เริ่มจริง
- commit ทั้งหมดมาจากบัญชีเดียว → อาจทำแทนกัน · ถามในสัมภาษณ์

## 5. ตรวจงาน `v1.0.0` (วันสอบ / หลังวันสอบ)

1. `git fetch --tags && git checkout v1.0.0` ในทุก repo
2. คัดลอก `check-project.mjs` ตัวจริงทับ → รันแบบ `--online --json` → เก็บไฟล์ผล
3. เปิด URL ที่ deploy · ทำ demo flow เอง 1 รอบ (ส่งคำขอ → login → เปลี่ยนสถานะ → ลบ · คนทั่วไปทำไม่ได้)
4. ให้คะแนนตาม `RUBRIC.md` ด้วยตาราง (แนะนำ Google Sheet: 1 แถว/คน · คอลัมน์ P1–P4 · I1–I3 · Q1–Q4 · ⭐)
5. รวมกับผลสัมภาษณ์ (ข้อ I1 = 0 ถ้าอธิบายงานของตัวเองไม่ได้)

| ใช้ผล checker ช่วยให้คะแนน | |
|---|---|
| P1 | B2.* ทั้งหมด + F1–F5 + ลองใช้งานจริง |
| P2 | D7 (`--online`) · กลุ่ม 3 คน X1–X4 |
| P3 | B1 + อ่าน `schema.sql` · `API_CONTRACT.md` |
| P4 | T2 · T3 · T5 + เปิดดู Issues / PR |
| Q1 | B3 · B4 · F6 |
| Q2 | B2.big · B2.noauth · B2.forbidden · B2.login · D3 · D4 · D5 · D8 |
| Q3 | B5 + อ่าน `DEBUG_LOG.md` |
| Q4 | T6 · D6 |
| I2 | `git log --author=<email> --format='%ad' --date=short \| sort -u \| wc -l` = จำนวนวันที่มี commit · `git shortlog -sne` |

> commit ใน `api/` ของคน Front-end (หรือกลับกัน) ไม่ผิด — แต่ I1 ดูจากงานในบทบาทของตัวเองเป็นหลัก
