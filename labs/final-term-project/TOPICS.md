# หัวข้อ Final Term Project

**เลือก 1 หัวข้อต่อทีม · ภายใน Section เดียวกันห้ามซ้ำ** — ใส่ 3 อันดับใน [`TEAM.md`](kit/TEAM.md) ตอน M0 · ผู้สอนจัดตามเวลาที่ส่งลิงก์ repo ใน LMS (ส่งก่อนได้ก่อน) · ข้าม Section ซ้ำได้ แต่โค้ดต้องไม่เหมือนกัน

ทุกหัวข้อมีรูปแบบเดียวกับ Campus Service — **คนทั่วไปส่งคำขอ · เจ้าหน้าที่ดูแลสถานะ** — แต่ข้อมูล กฎ และหน้าจอต่างกัน

| ทุกหัวข้อต้องมี | |
|---|---|
| ตารางหลัก | ≥ 6 ฟิลด์ รวม `status` · ฟิลด์ในตารางด้านล่างเป็น**ข้อเสนอ** ปรับได้ |
| ตารางที่เกี่ยวข้อง | ≥ 1 ตาราง (ไม่นับ `users`) เชื่อมด้วย FOREIGN KEY · API ส่งแบบ JOIN แล้ว |
| สถานะ | ใช้ตามตาราง หรือปรับได้ (ต้องมี 3–5 สถานะ) |
| กฎเฉพาะ | อย่างน้อย 1 ข้อ — ต้องมี unit test ค่าขอบ |

> อยากเสนอหัวข้อเอง? ใส่ใน `TEAM.md` ตอน M0 พร้อมกรอกครบทุกคอลัมน์แบบด้านล่าง · ผู้สอนอนุมัติภายใน 1 วัน

## ตัวอย่าง — แปลง Campus Service เป็น T07 (ยืม-คืนอุปกรณ์ชมรม)

| Campus Service (LAB 13) | T07 |
|---|---|
| ตาราง `requests` | ตาราง `loans` |
| ตาราง `users` (ผู้แจ้ง) | ยังใช้ `users` เป็นผู้ยืม + **เพิ่ม `equipment`** |
| `GET /api/requests` | `GET /api/loans` (JOIN `equipment` ให้ได้ชื่ออุปกรณ์) |
| `pending` · `in-progress` · `completed` | `requested` · `borrowed` · `returned` · `overdue` |
| รายละเอียด 10–1000 ตัวอักษร | วันคืนหลังวันยืมไม่เกิน 14 วัน · จำนวนไม่เกินที่มี |
| หน้า "แจ้งคำร้อง" | หน้า "ยืมอุปกรณ์" (เลือกอุปกรณ์จากรายการที่ดึงจาก API) |

> สิ่งที่**ไม่ต้องเปลี่ยน**: โครงชั้น route → controller → service · `config.js` · auth · health check · build/deploy — นี่คือประโยชน์ของการแยกชั้นที่เรียนมาทั้งภาค

**⚠ จุดที่ผูกกับชื่อ `requests` ไว้ — ลืมเปลี่ยนแล้วพังแบบเงียบ** (ทดลองแปลงเป็น T07 จริงแล้วเจอครบทั้ง 4 จุด)

| ไฟล์ (ใน LAB 13) | ผูกไว้กับ | ถ้าไม่เปลี่ยน |
|---|---|---|
| `api/src/services/requestService.js` → `loadSeed()` | `sqlite_master … name='requests'` | `schema.sql` (มี `DROP TABLE`) ถูกรัน**ทุกครั้งที่ start** → ข้อมูลหายทุก restart |
| `api/src/services/requestService.js` → `nextId()` | `LIKE 'REQ-%'` และ prefix `REQ-` | `POST` แรกได้ 500 หรือรหัสซ้ำ |
| `api/scripts/setup-db.mjs` | ข้อความและ foreign key ของ `requests` | `db:setup` รายงานผิดตาราง |
| `api/src/config.js` · `api/.env.example` | ไฟล์ `campus.db` | ใช้ได้ แต่ควรเปลี่ยนชื่อ เช่น `loans.db` |

**ตัวอย่างการตีความกฎของ T07** — ทีมเลือกเองได้ แต่ต้องเขียนไว้ใน README และมี test ยืนยัน

| คำถาม | ตัวอย่างที่ใช้ได้ |
|---|---|
| "จำนวนไม่เกินที่มี" นับอย่างไร | คงเหลือ = จำนวนทั้งหมด − ผลรวมจำนวนของรายการที่สถานะ `requested` · `borrowed` · `overdue` |
| "วันคืน" คือวันไหน | วัน**กำหนด**คืน (ไม่ต้องเก็บวันคืนจริงก็ได้ — สถานะ `returned` บอกแล้ว) |
| ใครเปลี่ยนเป็น `overdue` | เจ้าหน้าที่เปลี่ยนเองด้วย `PUT` (ไม่ต้องมีงานตั้งเวลา) |

ใช้หลักเดียวกันกับหัวข้ออื่นที่มีกฎกำกวม — **เลือก · เขียนไว้ · test ให้เห็น**
