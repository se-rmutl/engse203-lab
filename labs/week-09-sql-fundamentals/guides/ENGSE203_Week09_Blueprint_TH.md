## 1. จุดยืนของสัปดาห์นี้

```
Week 06–07            สัปดาห์ 9              สัปดาห์ 10           สัปดาห์ 11
API + เชื่อม React  →  SQL อย่างเดียว    →   Node + SQLite   →  MongoDB + integration
(ข้อมูลใน memory)      (ไม่แตะโค้ดเลย)        (async ของจริง)
```

**เหตุผลที่ไม่แตะ Node เลยทั้งคาบ**

นักศึกษา**ไม่เคยเจอ SQL มาก่อน** และจะได้เรียนวิชาฐานข้อมูลเทอมหน้า · ถ้าสอน SQL + แนวคิดเชิงสัมพันธ์ + การต่อ Node พร้อมกันในคาบเดียว จะเป็น 3 เรื่องใหม่ซ้อนกัน

เหมือน **CP00 ของ Week 06** ที่ให้ไปเล่น API ของจริงก่อนสร้างเอง — สัปดาห์นี้ให้เขียน SQL เห็นผลทันที ยังไม่ต้องกังวลเรื่องโค้ด

**ผลที่ได้** — สัปดาห์ 10 เริ่มจาก "ต่อ Node เข้ากับฐานข้อมูลที่ตัวเองสร้างไว้" ไม่ต้องย้อนสอน SQL อีก

## 2. สิ่งที่สัปดาห์นี้ต้องส่งมอบให้สัปดาห์ 10

นี่คือ **contract ระหว่างสองสัปดาห์** — ต้องได้ครบ ไม่งั้นสัปดาห์ 10 เริ่มไม่ได้

| ไฟล์ | คืออะไร | สัปดาห์ 10 ใช้ทำอะไร |
|---|---|---|
| `campus.db` | ฐานข้อมูลที่มีข้อมูลพร้อมใช้ | Node เปิดไฟล์นี้โดยตรง |
| `schema.sql` | คำสั่งสร้างฐานข้อมูลใหม่ทั้งหมด | สร้างใหม่ได้ถ้าไฟล์เสีย |
| `queries.sql` | คำสั่งค้นหาที่ทดสอบแล้ว | **คัดลอกไปใส่ใน service ได้เลย** |

> ข้อสุดท้ายสำคัญที่สุด — query ที่เขียนวันนี้จะกลายเป็นโค้ดในสัปดาห์หน้า

## 3. Data Model — 2 ตาราง

```
┌─────────────────┐          ┌──────────────────────┐
│ users           │          │ requests             │
├─────────────────┤          ├──────────────────────┤
│ id      (PK)    │◄────────┐│ id            (PK)   │
│ name            │         └│ requester_id  (FK)   │
│ department      │          │ request_type         │
│ email   (UNIQUE)│          │ location · details   │
└─────────────────┘          │ priority · status    │
                             │ created_at           │
                             └──────────────────────┘
```

**คำถามที่ใช้เปิดเรื่องการแยกตาราง**

> *"ตอน Week 06 เราเก็บ `requesterName` เป็นข้อความในทุกคำร้อง — ถ้าสมชายเปลี่ยนชื่อ ต้องแก้กี่ที่"*

### จุดสำคัญที่ต้องเน้นตอนท้ายคาบ

ผลของ `JOIN` **หน้าตาเหมือนข้อมูลที่ API ส่งให้ React ตอน Week 07 ทุกประการ**

> โครงในฐานข้อมูลไม่จำเป็นต้องเหมือนรูปแบบที่ API ส่งออก — **นี่คือหน้าที่ของชั้น service**

## 9. เรื่องที่เลื่อนไปสัปดาห์อื่น

| เรื่อง | ไปอยู่ที่ | เหตุผล |
|---|---|---|
| ต่อ Node กับ SQLite | สัปดาห์ 10 | แยกเรื่องใหม่ออกจากกัน |
| **ทำไม service ต้องเป็น async** | **สัปดาห์ 11** | `node:sqlite` เป็น sync — ถ้าสอน async ตอนใช้ SQLite จะดูเหมือนบังคับ · **MongoDB เป็น async จริงเพราะคุยข้ามเครือข่าย** เหตุผลจะเป็นของจริง |
| MongoDB + Mongoose | สัปดาห์ 11 | บีบเหลือ "เปรียบเทียบ + CRUD สั้น" |

**ประโยคที่จะใช้ในสัปดาห์ 11**

> *"SQLite อยู่ในเครื่องเลยเรียกตรง ๆ ได้ · แต่ MongoDB อยู่คนละเครื่อง ต้องรอ — ถ้าเขียน service เป็น async ไว้ตั้งแต่แรก เปลี่ยนฐานข้อมูลก็ไม่พัง"*
