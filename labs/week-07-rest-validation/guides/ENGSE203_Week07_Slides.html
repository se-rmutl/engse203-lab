W07 · บท 3 คำขอที่ถูกส่งไปถามก่อน

Preflight — POST ต้องขออนุญาตก่อน

// ① เบราว์เซอร์ส่งไปถามก่อน — เราไม่ได้เขียน มันทำเอง
OPTIONS /api/requests
Access-Control-Request-Method: POST

// ② เซิร์ฟเวอร์ตอบว่าอนุญาต
204 No Content
Access-Control-Allow-Methods: GET,POST,PUT,DELETE

// ③ เบราว์เซอร์ถึงจะส่งคำขอจริง
POST /api/requests

สังเกตใน DevTools — เวลากด POST จะเห็น 2 บรรทัดใน Network · OPTIONS ตามด้วย POST · ถ้าเห็นแค่ OPTIONS แปลว่า preflight ไม่ผ่าน

W07 · บท 3 ทดลองความเข้าใจ

เจอ CORS error ควรแก้ที่ไหน

Access to fetch at 'http://localhost:3001/api/requests'
from origin 'http://localhost:5173' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present.

ควรไปแก้ที่ไหน

เพราะเบราว์เซอร์ไม่ได้ดูว่าเราเขียนโค้ดยังไง — มันดูว่าเซิร์ฟเวอร์ส่ง Access-Control-Allow-Origin มาหรือเปล่า · เขียน fetch แบบไหนก็ไม่ช่วย

W07 · บท 6 จุดที่ต้องคิดเป็นพิเศษ

ทำไม 404 ต้องแปลงเป็น null

export async function getRequestById(requestId) {
  try {
    return await apiFetch(`/api/requests/${encodeURIComponent(requestId)}`);
  } catch (error) {
    // 404 ไม่ใช่ความผิดพลาดของระบบ — แปลว่าไม่มีคำร้องรหัสนี้
    if (error instanceof ApiError && error.status === 404) return null;
    throw error;
  }
}

W07 · บท 7 อย่าให้ผู้ใช้เห็นข้อความเทคนิค

error ต่างกัน ควรบอกต่างกัน

statusเกิดอะไรขึ้นควรบอกผู้ใช้ว่า
0ต่อ API ไม่ได้เลย"ติดต่อเซิร์ฟเวอร์ไม่ได้ — ตรวจว่าเปิด API แล้วหรือยัง"
400ข้อมูลที่ส่งไปผิดข้อความจาก API ที่บอกว่าผิดตรงไหน
404ไม่พบสิ่งที่ขอ"ไม่พบคำร้องรหัสนี้" — ไม่ใช่หน้า error
500เซิร์ฟเวอร์พัง"เกิดข้อผิดพลาด ลองใหม่อีกครั้ง"

TypeError: Failed to fetch ไม่มีความหมายกับผู้ใช้ทั่วไป — แปลเป็นภาษาคนที่บอกว่าควรทำอะไรต่อ · นี่คือเหตุผลที่เราสร้าง ApiError พร้อมข้อความไทย

cleanup guard จาก Week 05 จะได้ใช้จริงแล้ว — ตอนนั้นเห็นผลยากเพราะข้อมูลมาเร็ว · ตอนนี้เรียกข้ามเครื่อง ความช้าเป็นเรื่องจริง
