W06 · บท 1 เทียบกับของที่คุ้น

Frontend / Backend = หน้าร้าน / ครัว

🍽️

Frontend = หน้าร้าน

เมนู โต๊ะ สิ่งที่ลูกค้าเห็น · React, HTML, CSS · อยู่ที่เครื่องผู้ใช้แต่ละคน

👨‍🍳

Backend = ครัว

ลูกค้าไม่เห็น · ทำอาหารตามออเดอร์ · มีที่เดียวรับออเดอร์จากทุกโต๊ะ

ครัวมีที่เดียว แต่รับออเดอร์จากทุกโต๊ะ — เหมือนเซิร์ฟเวอร์ที่รับคำขอจากผู้ใช้ทุกคน · ลูกค้า (เบราว์เซอร์) สั่งอาหาร (ส่ง request) ครัวทำเสร็จส่งกลับ (response)

W06 · บท 2 พื้นฐาน

Node.js — JavaScript นอกเบราว์เซอร์

JS ในเบราว์เซอร์

  • จัดการหน้าเว็บ DOM
  • fetch, localStorage
  • อ่านไฟล์ไม่ได้
  • เป็นเซิร์ฟเวอร์ไม่ได้

Node.js

  • engine V8 ตัวเดียวกับ Chrome
  • อ่านเขียนไฟล์ได้

ภาษาเดิม ความสามารถมากขึ้น — ใช้ JavaScript ที่เขียน React มาเขียนเซิร์ฟเวอร์ได้เลย ไม่ต้องเรียนภาษาใหม่

W06 · บท 4 เครื่องมือหลัก

ทำไมใช้ Express ไม่เขียน Node เปล่า

Node เปล่า

if (req.url === '/' &&
    req.method === 'GET') {
  res.writeHead(200, {...});
  res.end('hello');
}

เช็ค url + method เอง ทุกครั้ง

Express

app.get('/', (req, res) => {
  res.send('hello');
});

สั้น ชัด โฟกัสที่ตรรกะ

เหมือน React ช่วยจัดการ DOM — เราไม่ต้องเขียน document.createElement เอง · Express ช่วยจัดการงานซ้ำ ๆ ของเซิร์ฟเวอร์ให้

W06 · บท 4 โครงพื้นฐาน

เซิร์ฟเวอร์ Express มี 3 ส่วน

// 1 · สร้าง app
const app = express();

// 2 · กำหนด route
app.get('/api/requests', (req, res) => {
  res.json(requests);
});

// 3 · เปิดรับคำขอ
app.listen(3001);

CP01 คือการเขียน 3 ส่วนนี้ — สร้าง app → กำหนด route → เปิดรับคำขอ · เปิด browser แล้วเห็นเซิร์ฟเวอร์ตอบ

W06 · บท 5 เทียบกับ Week 05

Routing — จับคู่ URL กับสิ่งที่ทำ

⚛️

React Router (W05)

URL เปลี่ยน → เลือก component ไหนแสดง · ทำในเบราว์เซอร์

🖥️

Express routing (W06)

คำขอเข้ามา → เลือกโค้ดไหนตอบ · ทำในเซิร์ฟเวอร์

แนวคิดเดียวกัน — "จับคู่ URL กับสิ่งที่จะทำ"

app.get('/api/requests/:id', (req, res) => {
  const id = req.params.id;   // :id คือส่วนที่เปลี่ยนได้
});
W06 · บท 5 ทดลองความเข้าใจ

กับดักลำดับ route

app.get('/api/requests/:id', ...)    // เขียนก่อน
app.get('/api/requests/new', ...)    // เขียนหลัง

เมื่อมีคำขอ GET /api/requests/new เข้ามา จะเกิดอะไร

กฎ — เขียน route เจาะจง (path คงที่) ก่อน route ที่มีตัวแปร :id เสมอ

W06 · บท 7 กับดัก

ลำดับ middleware สำคัญมาก

ถ้าเขียน express.json() หลัง route — route นั้นอ่าน body ไม่ได้ เพราะ middleware ยังไม่ทำงานตอน route ทำ

app.post('/api/requests', ...)   // route เขียนก่อน
app.use(express.json())          // json ทำงานทีหลัง = สาย!

กฎ — middleware ที่ใช้กับทุก route เขียน ก่อน route ทั้งหมดเสมอ · เหมือน AppLayout ใน W05 ที่เขียน header ครั้งเดียวใช้ทุกหน้า

W06 · บท 8 มาตรฐานโลก

REST — path เป็นคำนาม การกระทำอยู่ที่ method

method + pathทำอะไร
GET /api/requestsดูทั้งหมด
GET /api/requests/:idดูใบเดียว
POST /api/requestsสร้างใหม่
DELETE /api/requests/:idลบ

path เดียวกันทำได้หลายอย่างตาม method · ตรงกับ requestService.js ของ React ที่มีอยู่แล้ว

W06 · บท 8 ทดลองความเข้าใจ

อันไหน RESTful

"ลบคำร้อง REQ-001" แบบ RESTful ควรเป็น

อย่าเอาคำกริยาใส่ path — ไม่ใช่ /deleteRequest · ให้ method (DELETE) บอกการกระทำ path บอกแค่ทรัพยากร

W06 · บท 9 บอกผลด้วยตัวเลข

Status Code — จำเป็นกลุ่ม

2xx · สำเร็จ

200 OK · 201 Created · 204 No Content

4xx · ผู้ใช้ผิด

400 Bad Request · 404 Not Found

5xx · เซิร์ฟเวอร์ผิด

500 Internal Server Error · โค้ดเราพังเอง

จำ 6 ตัว: 200 · 201 · 204 · 400 · 404 · 500

W06 · บท 9 ทดลองความเข้าใจ

POST สำเร็จ — 200 หรือ 201

สร้างคำร้องใหม่สำเร็จ ควรตอบ status อะไร

201 Created บอกว่าสำเร็จและมีของใหม่ถูกสร้าง · ส่วน 200 แปลว่าสำเร็จเฉย ๆ · ใช้ 200 ไม่ผิด แต่ 201 สื่อชัดกว่าและเป็นมาตรฐาน REST · คุณเห็นของจริงมาแล้วใน API Playground!
