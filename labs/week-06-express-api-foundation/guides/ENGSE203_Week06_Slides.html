04

Express — เครื่องมือที่ทำให้เขียนเซิร์ฟเวอร์ง่ายขึ้น

Node เขียนเซิร์ฟเวอร์ได้อยู่แล้ว แต่เขียนเองทุกอย่างจะยาวและพลาดง่าย Express ช่วยตรงไหน

🏫 เรียนและลงมือในห้อง≈ 9 นาที
บทที่ 4 / 12 · Express เครื่องมือหลัก

ทำไมใช้ Express ไม่เขียน Node เปล่า

Node เปล่า — 12 บรรทัด

const server = http.createServer((req,res)=>{
  if(req.url==='/' && req.method==='GET'){
    res.writeHead(200,{...});
    res.end('hello');
  } else { res.writeHead(404); res.end(); }
});

เช็ค url + method เอง · ตั้ง header เอง · 10 route = if ซ้อน 10 ชั้น

Express — 3 บรรทัด

app.get('/', (req, res) => {
  res.send('hello');
});

บอกแค่ "ถ้ามี GET ที่ / ให้ทำแบบนี้" · Express จัดการที่เหลือ

เหมือน React ช่วยจัดการ DOM — เราไม่ต้องเขียน document.createElement เอง · Express ก็ช่วยจัดการงานซ้ำ ๆ ของเซิร์ฟเวอร์ให้ เราโฟกัสที่ตรรกะได้เลย

บทที่ 4 / 12 · Express ภาพรวมทั้งระบบ

วงจรชีวิตของคำขอหนึ่งครั้ง

บทที่ 4 / 12 · Express โครงพื้นฐาน 🏫 ทำในห้อง

เซิร์ฟเวอร์ Express มี 3 ส่วนเสมอ

// ① สร้าง app
import express from 'express';
const app = express();

// ② กำหนด route
app.get('/', (req, res) => {
  res.send('API is running');
});

// ③ เปิดรับคำขอ
app.listen(3001, () => {
  console.log('พร้อมที่ port 3001');
});

① สร้าง app

เริ่มต้นเซิร์ฟเวอร์เปล่า

② กำหนด route

path ไหน ทำอะไร

③ เปิดรับคำขอ

เริ่มรอที่พอร์ต 3001

✓ CP01 ผ่านเมื่อ — เปิด http://localhost:3001 ในเบราว์เซอร์แล้วเห็นข้อความ "API is running"

บทที่ 4 / 12 · Express

จบบทที่ 4 — Express

✓ สิ่งที่ต้องจำจากบทนี้

  • Node เปล่า ๆ ต้องแยก method/path เอง แปลง JSON เอง — ยาวและพลาดง่าย
  • Express จัดการเรื่องซ้ำ ๆ ให้ เหลือแค่เขียนว่า "คำขอแบบนี้ ตอบแบบนี้"
  • เซิร์ฟเวอร์ Express มี 3 ส่วน — สร้าง app · ผูก route · เปิดรับที่พอร์ต
ต่อไป → ลงมือ CP01 — Hello Server ตัวแรก แล้วเข้าบทที่ 5
🏫 ลงมือทำ · CP01 ใช้ความรู้บทที่ 4

CP01 · Hello Server

import express from 'express';

const app = express();               // ① สร้าง app

app.get('/', (req, res) => {          // ② ผูก route
  res.json({ message: 'Campus Service API is running' });
});

app.listen(3001, () => {            // ③ เปิดรับที่พอร์ต
  console.log('พร้อมที่ http://localhost:3001');
});

✓ ผ่านเมื่อ — เปิด http://localhost:3001 ในเบราว์เซอร์แล้วเห็น JSON · และ terminal ไม่มี error

ถ้าได้ EADDRINUSE แปลว่าพอร์ต 3001 ถูกใช้อยู่ — มีเซิร์ฟเวอร์เก่าค้างอยู่ ให้ปิดก่อนด้วย Ctrl+C

06

Request และ Response

อ่านข้อมูลจากคำขอได้ 3 ทาง และเขียนคำตอบกลับให้ถูกรูปแบบ พร้อมกฎเหล็กข้อหนึ่งที่พลาดกันบ่อย

🏫 เรียนและลงมือในห้อง≈ 10 นาที
บทที่ 6 / 12 · req / res อ่านคำขอ · เขียนคำตอบ

req อ่านอะไรได้ · res เขียนอะไรได้

req — อ่านคำขอ

req.params.idค่าจาก :id
req.query.statusค่าหลัง ?
req.bodyข้อมูลจาก POST
req.methodGET / POST / …

res — เขียนคำตอบ

res.json(data)ส่ง JSON กลับ
res.status(201)ตั้งรหัสสถานะ
res.status(404).json()ต่อกันได้
res.end()จบโดยไม่ส่งข้อมูล

🟥 กับดักอันดับ 1 ของมือใหม่ — ถ้าลืม app.use(express.json()) แล้ว req.body จะเป็น undefined ตลอด · POST จะพังโดยไม่มี error บอกสาเหตุ

บทที่ 6 / 12 · req / res กฎเหล็กที่พลาดกันบ่อยที่สุด

ตอบสองครั้งแล้วเกิดอะไรขึ้น

✕ ผิด — ลืม return

app.get('/:id', (req, res) => {
  const item = find(req.params.id);

  if (!item) {
    res.status(404).json({ error: 'ไม่พบ' });
  }
  res.json(item);  // ← ทำงานต่อ!
});

✓ ถูก — มี return

app.get('/:id', (req, res) => {
  const item = find(req.params.id);

  if (!item) {
    return res.status(404).json({ error: 'ไม่พบ' });
  }
  res.json(item);
});

error ที่จะเจอ — ERR_HTTP_HEADERS_SENT: Cannot set headers after they are sent
แปลว่า "ส่งคำตอบไปแล้ว จะส่งซ้ำอีกไม่ได้" · เหมือนส่งจดหมายออกไปแล้วจะกลับไปแก้ข้างในไม่ได้

ทำไมเจอบ่อย

res.json() ไม่ได้หยุดการทำงานของฟังก์ชัน — มันแค่ส่งคำตอบ แล้วบรรทัดถัดไปก็ยังทำงานต่อ
กฎง่าย ๆ: ทุกครั้งที่เขียน res. ใน if ให้ใส่ return นำหน้าเสมอ

function logger(req, res, next) {

ปัญหาที่ ②

stack trace บอกโครงสร้างไฟล์ในเครื่องเซิร์ฟเวอร์

บทที่ 11 / 12 · Error Handling กับดักที่สำคัญที่สุดของบทนี้

middleware ตัวสุดท้ายที่รับ error ทั้งหมด

// ⚠ ต้องมี 4 พารามิเตอร์ ห้ามขาด
export function errorHandler(err, req, res, next) {
  const status = err.status ?? 500;

  if (status >= 500) console.error(err.message);   // เราดูเอง

  res.status(status).json({
    error: status >= 500 ? 'เกิดข้อผิดพลาดภายในเซิร์ฟเวอร์' : err.message,
  });
}

ถ้าเขียน (err, req, res) แค่ 3 ตัว — Express จะไม่เรียกมันเลย
เพราะ Express นับจำนวนพารามิเตอร์ เพื่อแยกว่าเป็น error handler หรือ middleware ธรรมดา
โค้ดจะดูถูกทุกอย่าง รันได้ ไม่มี error บอก — แต่ไม่ทำงาน · เป็นจุดที่รุ่นก่อนติดนานที่สุด

วิธีส่ง error ไปที่นี่ — ใน controller ใช้ next(err) ไม่ต้องตอบเอง

บทที่ 11 / 12 · Error Handling เชื่อมกับบทที่ 7

errorHandler ต้องอยู่ล่างสุดเสมอ

app.use(logger);                     // ① middleware ทั่วไป
app.use(express.json());
app.use('/api/requests', routes);      // ② route
app.use(notFound);                   // ③ ไม่ตรง route ไหนเลย → 404
app.use(errorHandler);               // ④ ต้องเป็นตัวสุดท้ายเสมอ

ทำไม errorHandler ต้องอยู่ล่างสุด

เพราะมันคือ "ตาข่ายรองรับ" ที่ดักทุกอย่างที่หลุดมา — ถ้าวางไว้บน จะไม่มีอะไรหลุดมาถึง
นี่คือเรื่องลำดับของ middleware ที่เรียนในบทที่ 7 อีกครั้ง แต่คราวนี้เห็นผลชัดกว่า

notFound วางหลัง route ทั้งหมด — คำขอที่มาถึงตรงนี้แปลว่าไม่ตรงกับ route ไหนเลย จึงตอบ 404 เป็น JSON

วิธีเก็บลงไฟล์ JSON

import { readFile, writeFile } from 'node:fs/promises';

// ① อ่านครั้งเดียวตอนเซิร์ฟเวอร์เริ่ม
export async function loadSeed() {
  try { requests = JSON.parse(await readFile(FILE, 'utf8')); }
  catch { requests = []; }    // ไฟล์ยังไม่มี = เริ่มจากว่าง ไม่ใช่ error
}

// ② เขียนทุกครั้งที่ข้อมูลเปลี่ยน
async function persist() {
  await writeFile(FILE, JSON.stringify(requests, null, 2), 'utf8');
}

① ลืม await — writeFile เป็น async · ไม่ await = ตอบ 201 ไปแล้วแต่ไฟล์ยังไม่ถูกเขียน

② ไฟล์ยังไม่มีแล้วโยน error — ครั้งแรกที่รัน data/requests.json ยังไม่มี ต้อง try/catch

③ ลืมสร้างโฟลเดอร์ data/ — writeFile ไม่สร้างให้ · ไม่มีจะได้ ENOENT

เรียก persist() เฉพาะฟังก์ชันที่เปลี่ยนข้อมูล — add · remove · updateStatus · ส่วน getAll กับ getById ไม่ต้อง
