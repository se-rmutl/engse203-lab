00a

เปิด public API ในเบราว์เซอร์

8 นาที · We do

ผู้สอนเปิดบนจอก่อน แล้วให้ทุกคนเปิดตาม

https://jsonplaceholder.typicode.com/posts/1

จะได้ JSON แบบนี้กลับมา

{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere...",
  "body": "quia et suscipit..."
}
ถามห้อง 3 คำถาม หนึ่ง — ข้อมูลนี้มี field อะไรบ้าง
สอง — เหมือนหรือต่างจากข้อมูลคำร้องในแอปเราอย่างไร
สาม — ลองเปลี่ยนเลขท้ายเป็น 2, 50, 9999 แล้วเกิดอะไรขึ้น
จุดที่ต้องชี้ให้เห็น เปลี่ยนเป็น 9999 แล้วได้ {} ว่าง ๆ — นี่คือกรณี "ไม่พบ" ซึ่งเดี๋ยวเราจะทำให้ API ของเราตอบ 404 พร้อมข้อความที่ดีกว่านี้
เชื่อมกับของเรา "โครง posts นี้คล้ายกับ requests ของเราเลย — มี id กับ field ข้อมูล · สิ่งที่เราจะสร้างวันนี้ก็หน้าตาแบบนี้ แต่เป็นคำร้องแทนโพสต์"
00b

ดู request/response จริงด้วย DevTools

10 นาที · We do → ลองเอง

ผู้สอนสาธิตบนจอ แล้วให้ทุกคนทำตามบนเครื่องตัวเอง

  1. เปิดเว็บอะไรก็ได้ที่ใช้ประจำ
  2. กด F12 → เลือกแท็บ Network
  3. กด F5 รีเฟรชหน้า
  4. ดูรายการ request ที่โผล่ขึ้นมา
  5. คลิกที่ request หนึ่งอัน → ดูแท็บ Headers และ Response
ให้หาสิ่งเหล่านี้ให้เจอ request ที่ method เป็น GET · request ที่ได้ 200 · request ที่ได้ JSON กลับมา (ดูคอลัมน์ Type)
ทักษะที่ต้องได้จากช่วงนี้ ชี้ได้ว่า method, status code, request body, response อยู่ตรงไหนในหน้าจอ DevTools
เพราะทั้งเทอมที่เหลือจะใช้ทักษะนี้ debug ตลอด
ถ้าเน็ตห้องช้าหรือใช้ไม่ได้ ให้ดูบนจอผู้สอนอย่างเดียว แล้วให้ไปลองเองที่บ้าน · อย่าเสียเวลาเกิน 10 นาที เพราะเนื้อหาหลักอยู่ช่วงเขียนโค้ด
00c

ยิง request เองด้วย Postman

12 นาที · You do

เบราว์เซอร์ยิงได้แค่ GET · ถ้าอยากลอง POST ต้องใช้เครื่องมือเฉพาะ

เครื่องมือข้อดีเหมาะกับ
Postmanครบเครื่อง เก็บ collection ได้มาตรฐานอุตสาหกรรม
Thunder Clientอยู่ใน VS Code เบา ไม่ต้องสลับหน้าต่างทดสอบเร็ว ๆ

ให้นักศึกษายิง 3 request นี้แล้วบันทึก status ที่ได้

#MethodURLstatus
1GET.../posts______
2GET.../posts/1______
3POST.../posts______

สำหรับข้อ 3 — Body → raw → JSON

{ "title": "ทดสอบ", "body": "เนื้อหา", "userId": 1 }
ถามหลังทุกคนยิงเสร็จ "ข้อ 3 ได้ status อะไรครับ" — รอให้มีคนตอบว่า 201
"ทำไมไม่ใช่ 200 ทั้งที่ก็สำเร็จเหมือนกัน" — ยังไม่ต้องเฉลย บอกว่า "เดี๋ยวเราจะรู้คำตอบตอนบ่าย"
ทำไมต้องปล่อยให้สงสัย พอถึงบทที่ 9 เรื่อง status code นักศึกษาจะจำได้ทันทีว่า "อ๋อ ที่เจอเมื่อเช้าคือ 201 Created นี่เอง" — ความรู้ที่ผูกกับประสบการณ์จะติดทนกว่า
✓

ผ่าน CP00 เมื่อ

✓เปิด public API ในเบราว์เซอร์แล้วเห็น JSON
✓ชี้ได้ว่าใน DevTools Network method/status อยู่ตรงไหน
✓ยิง GET และ POST ด้วย Postman/Thunder Client ได้
✓สังเกตได้ว่า POST สำเร็จได้ 201 ไม่ใช่ 200
คำถาม Checkpoint ทำไม POST สำเร็จถึงได้ 201 ไม่ใช่ 200
ยังไม่ต้องได้คำตอบที่ถูกตอนนี้ — เก็บไว้ถามซ้ำหลังบทที่ 9
ประโยคเชื่อมไปช่วงถัดไป "ทีนี้เราเห็นแล้วว่า API ที่คนอื่นทำหน้าตาเป็นอย่างไร — ต่อไปเราจะสร้างของเราเอง เปิด VS Code กันเลยครับ"
