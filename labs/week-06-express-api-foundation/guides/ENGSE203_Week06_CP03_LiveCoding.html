อธิบายแนวคิดก่อนพิมพ์

5 นาที · I do
เปิดด้วยอุปมา "middleware เหมือนด่านตรวจที่สนามบิน — ก่อนขึ้นเครื่อง (handler) คุณต้องผ่านหลายด่านเรียงกัน: เช็คอิน → ตรวจกระเป๋า → ตรวจหนังสือเดินทาง
แต่ละด่านทำหน้าที่ของตัวเองแล้วส่งต่อด่านถัดไป" 
request → logger → express.json() → handler → response
          ↑ ด่าน 1   ↑ ด่าน 2      ↑ ปลายทาง
ทำไมถึงมีประโยชน์ "แทนที่จะเขียน 'บันทึก log' ในทุก route (ซ้ำ 10 ที่) เราเขียน middleware ตัวเดียวแล้วทุกคำขอผ่านมันอัตโนมัติ
เป็นหลักการเดียวกับ AppLayout ใน Week 05 ที่เขียน header ครั้งเดียวใช้ทุกหน้า"
ย้ำเรื่อง next() "middleware มี 3 พารามิเตอร์ ต่างจาก handler ที่มี 2 — ตัวที่เพิ่มมาคือ next
ถ้าลืมเรียก next() คำขอจะค้างอยู่ตรงนั้น ไม่มีวันถึง handler ผู้ใช้จะรอคำตอบไปเรื่อย ๆ จนหมดเวลา"
1

เขียน logger middleware

src/middleware/logger.js · TODO W06-M1
export function logger(req, res, next) {
  const start = Date.now();

  res.on('finish', () => {
    const ms = Date.now() - start;
    console.log(`${req.method} ${req.originalUrl} → ${res.statusCode} (${ms}ms)`);
  });

  next();                     ← ห้ามลืม!
}
อธิบาย res.on('finish') "ทำไมไม่พิมพ์ทันที — เพราะตอนที่ middleware ทำงาน เรายังไม่รู้ว่าจะตอบ status อะไร
res.on('finish') คือการบอกว่า 'พอตอบเสร็จแล้วค่อยพิมพ์' ซึ่งตอนนั้นเรารู้ status แล้ว"
ถ้าไม่อยากซับซ้อน ทำแบบง่ายก่อนก็ได้ 
console.log(`${req.method} ${req.url}`);
next();

แล้วค่อยเพิ่ม status กับเวลาทีหลัง — สำหรับห้องที่ตามช้า

ติดตั้งใน app.js

src/app.js · TODO W06-A1
app.use(logger);            ← ① บันทึกทุกคำขอ
app.use(express.json());   ← ② ทำให้ req.body อ่านได้

// route ทั้งหมดอยู่ข้างล่างนี้
express.json() คืออะไร ทำไมต้องมี "โดยค่าเริ่มต้น Express ไม่รู้จะอ่าน body อย่างไร — ถ้าไม่มีบรรทัดนี้ req.body จะเป็น undefined ตลอด
ตอนนี้ยังไม่เห็นผล เพราะเรายังไม่มี POST — แต่พอถึง CP04 ถ้าลืมบรรทัดนี้จะพังทันที"
ทดสอบทันที ยิง request อะไรก็ได้ แล้วดู terminal ที่รันเซิร์ฟเวอร์ 
GET /api/requests → 200 (2ms)
GET /api/requests/REQ-999 → 404 (1ms)

สาธิตว่าลำดับสำคัญ

5 นาที · I do — สาธิตแล้วแก้กลับ
สาธิตแบบผิดให้ดู "ผมจะย้าย app.use(logger) ไปไว้ล่างสุดหลัง route แล้วดูว่าเกิดอะไร"
ย้ายไปล่าง 
app.use('/api/requests', routes);
app.use(logger);   ← สายไป

ยิง request → terminal เงียบ ไม่มี log

ย้ายกลับขึ้นบน 
app.use(logger);   ← ทันเวลา
app.use('/api/requests', routes);

ยิง request → log ออกมาปกติ

สรุปเป็นกฎบนกระดาน middleware ที่ใช้กับทุก route ต้องเขียนก่อน route ทั้งหมดเสมอ
เพราะ Express ทำงานตามลำดับที่เขียน — ถ้า route ตอบไปแล้ว middleware ที่อยู่ล่างจะไม่มีโอกาสทำงาน
อย่าลืมแก้กลับ สาธิตเสร็จแล้วย้าย logger กลับขึ้นบนก่อนไปต่อ · ให้นักศึกษาตรวจว่าของตัวเองอยู่ถูกที่
!

กับดัก 2 อันของช่วงนี้

อันตรายที่สุด ลืมเรียก next()

อาการ — Postman ค้างหมุนไปเรื่อย ๆ ไม่มีคำตอบกลับมา · terminal อาจเห็น log แต่ไม่มีอะไรตอบ

วิธีเช็ค — ดูว่าใน logger มี next(); ท้ายฟังก์ชันหรือไม่

เจอตอน CP04 ลืม express.json()

req.body เป็น undefined → POST พังโดยไม่มี error บอกสาเหตุ · กับดักอันดับ 1 ของมือใหม่ — ให้ตรวจตอนนี้เลยว่ามีบรรทัดนี้แล้ว

อาการสาเหตุ
terminal ไม่มี log เลยลืม app.use(logger) หรือเขียนหลัง route
Postman ค้าง ไม่ตอบลืม next()
log ออกแต่ status เป็น undefinedพิมพ์ทันทีแทนที่จะรอ res.on('finish')
✓

ผ่าน CP03 เมื่อ

checker ตรวจข้อนี้ไม่ได้ checker ยิง request ได้ แต่อ่าน log ใน terminal ไม่ได้ · ต้องเดินดูหน้าจอนักศึกษาว่า log ออกมาจริงหรือไม่

✓log แสดง method, path และ status code ถูกต้อง
