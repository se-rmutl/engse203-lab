W06 · บท 4 เครื่องมือหลัก

ทำไมใช้ Express ไม่เขียน Node เปล่า

Node เปล่า — 12 บรรทัด

const server = http.createServer((req,res)=>{
  if(req.url==='/' && req.method==='GET'){
    res.writeHead(200,{...});
    res.end('hello');
  } else { res.writeHead(404); res.end(); }
});

เช็ค url + method เอง · ตั้ง header เอง · 10 route = if ซ้อน 10 ชั้น

Express — 3 บรรทัด

app.get('/', (req, res) => {
  res.send('hello');
});

บอกแค่ "ถ้ามี GET ที่ / ให้ทำแบบนี้" · Express จัดการที่เหลือ

เหมือน React ช่วยจัดการ DOM — เราไม่ต้องเขียน document.createElement เอง · Express ก็ช่วยจัดการงานซ้ำ ๆ ของเซิร์ฟเวอร์ให้ เราโฟกัสที่ตรรกะได้เลย

route ที่เซิร์ฟเวอร์มี — กดปุ่มดูว่าคำขอไหนเข้า route ไหน

ROUTE ที่ถูกเลือก

W06 · บท 5 กับดักที่พบบ่อย

ลำดับ route สำคัญ

app.get('/api/requests/:id', ...)    // เขียนก่อน
app.get('/api/requests/new', ...)    // เขียนหลัง

คำขอ GET /api/requests/new จะเข้า route ไหน

Express เลือก route ที่เขียนไว้ก่อน · กฎ — เขียน route เจาะจง (path คงที่) ก่อน route ที่มีตัวแปร :id เสมอ

W06 · บท 6 อ่านคำขอ · เขียนคำตอบ

req อ่านอะไรได้ · res เขียนอะไรได้

req — อ่านคำขอ

req.params.idค่าจาก :id
req.query.statusค่าหลัง ?
req.bodyข้อมูลจาก POST
req.methodGET / POST / …

res — เขียนคำตอบ

res.json(data)ส่ง JSON กลับ
res.status(201)ตั้งรหัสสถานะ
res.status(404).json()ต่อกันได้
res.end()จบโดยไม่ส่งข้อมูล

🟥 กับดักอันดับ 1 ของมือใหม่ — ถ้าลืม app.use(express.json()) แล้ว req.body จะเป็น undefined ตลอด · POST จะพังโดยไม่มี error บอกสาเหตุ

W06 · CP03 · 🏫 กับดัก 🏫 ทำในห้อง

ลำดับ middleware สำคัญมาก

function logger(req, res, next) {
  console.log(`${req.method} ${req.url}`);  // ทำงานของตัวเอง
  next();                               // ส่งต่อชั้นถัดไป
}

app.use(logger);              // ① เขียนก่อน route
app.use(express.json());     // ② เขียนก่อน route
app.get('/api/requests', ...)  // ③ route มาทีหลัง

ถ้าสลับลำดับ — เขียน express.json() หลัง route แล้ว route นั้นจะอ่าน req.body ไม่ได้ เพราะ middleware ยังไม่ทำงานตอนที่ route ทำ

กฎ — middleware ที่ใช้กับทุก route เขียน ก่อน route ทั้งหมดเสมอ · เหมือน AppLayout ใน Week 05 ที่เขียน header ครั้งเดียวใช้ได้ทุกหน้า

POST สำเร็จ — 200 หรือ 201

เชื่อมกับ Week 05 — ตอนนั้นเราเขียน if (!response.ok) throw ... · response.ok เป็น true เมื่อ status เป็น 2xx · ตอนนี้คุณรู้แล้วว่าตัวเลขนั้นมาจากไหน — จากฝั่งเซิร์ฟเวอร์ที่เรากำลังเขียนนี่เอง
