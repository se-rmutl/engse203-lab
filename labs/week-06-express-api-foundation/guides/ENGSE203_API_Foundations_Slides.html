API · INTRO ก่อนอื่น — ขอถามตรง ๆ

คุณสร้าง API ได้ แต่ตอบคำถามพวกนี้ได้ไหม

  • ก่อนจะมี API โลกเขาทำกันอย่างไร
  • ทำไมยุคนี้ถึงเลือก "API เป็นหลังบ้าน" ไม่ใช่แบบอื่น

  • "ful" ใน RESTful แปลว่าอะไร

ถ้าตอบไม่ได้ ไม่ใช่ความผิดของคุณ — เราข้ามเรื่องนี้ไปเพื่อให้ลงมือทำได้เร็ว · วันนี้เรากลับมาเติมช่องว่างนี้

API · บท 1 ย้อนอดีต

ก่อนจะมี API เว็บทำงานอย่างไร

API · บท 1 ทดลองความเข้าใจ

ถ้าเซิร์ฟเวอร์ส่ง HTML มาอย่างเดียว

บริษัทอยากทำแอปมือถือเพิ่ม โดยใช้ข้อมูลชุดเดียวกัน — ปัญหาคืออะไร

แอปมือถือวาดหน้าจอเอง — มันต้องการแค่ ข้อมูลดิบ ไม่ใช่ HTML สำเร็จรูป
ถ้าเซิร์ฟเวอร์ส่งได้แต่ HTML ก็ต้องสร้างเซิร์ฟเวอร์อีกชุดให้มือถือโดยเฉพาะ — ดูแล 2 ชุด ข้อมูลอาจไม่ตรงกัน

API · Application Programming Interface

ช่องทางที่โปรแกรมหนึ่งเรียกใช้อีกโปรแกรมหนึ่ง โดยไม่ต้องรู้ว่าข้างในทำงานอย่างไร

คุณใช้ API มาตลอดโดยไม่รู้ตัว

ชนิดของ APIตัวอย่างที่คุณเคยใช้
Library APIMath.random() · array.map() — เรียกใช้โดยไม่รู้ว่าข้างในเขียนยังไง
Browser APIfetch() · localStorage · document.querySelector()
OS APIโปรแกรมขอเปิดไฟล์ · ขอใช้กล้อง
Web API ← ที่เรากำลังเรียนเรียกข้ามเครื่องผ่านเครือข่าย

คำสำคัญคือ "Interface" — หน้าสัมผัส · เหมือนปลั๊กไฟ คุณเสียบได้โดยไม่ต้องรู้ว่าไฟมาจากเขื่อนหรือโรงไฟฟ้า

API · บท 4 ที่มาที่ไป

REST มาจากไหน ใครคิด

Roy Fielding · ปี 2000 · วิทยานิพนธ์ปริญญาเอก

เขาเป็นหนึ่งในคนที่ออกแบบ HTTP เอง — แล้วเขียนวิทยานิพนธ์อธิบายว่าทำไมเว็บถึงขยายตัวได้มหาศาลโดยไม่พัง

REST · REpresentational State Transfer

ไม่ใช่เทคโนโลยี ไม่ใช่ protocol ไม่ใช่ library — แต่เป็น "รูปแบบสถาปัตยกรรม" (architectural style) คือชุดหลักการว่าควรออกแบบระบบอย่างไรให้ขยายตัวได้ดี

เพราะฉะนั้น — ไม่มีใคร "ติดตั้ง REST" ได้ · ไม่มี npm install rest · REST คือวิธีคิด ไม่ใช่ของที่ลงได้

API · บท 4 หัวใจที่สุดของ REST

Uniform Interface — ทำไมถึงสำคัญที่สุด

เทียบกับปลั๊กไฟ — ถ้าทุกยี่ห้อออกแบบปลั๊กของตัวเอง คุณต้องซื้ออะแดปเตอร์ทุกครั้งที่เปลี่ยนเครื่องใช้ไฟฟ้า
แต่เพราะทุกคนใช้มาตรฐานเดียวกัน — เสียบอะไรก็ได้ ไม่ต้องอ่านคู่มือ

API ก็เหมือนกัน — พอทุกคนใช้กติกาเดียวกัน เจอ API ไหนก็เดาได้ทันที

เจอ API ใหม่ที่ไม่เคยใช้คุณเดาได้ทันทีว่า
GET /usersดูผู้ใช้ทั้งหมด
GET /users/42ดูผู้ใช้คนที่ 42
POST /usersสร้างผู้ใช้ใหม่
DELETE /users/42ลบผู้ใช้คนที่ 42

ไม่ต้องอ่านคู่มือเลยสักบรรทัด — นี่คือพลังของ uniform interface · GitHub, Google, ธนาคาร ก็ใช้รูปแบบเดียวกันนี้

API · บท 6 คำที่ใช้กันแต่ไม่ค่อยมีใครอธิบาย

"ful" ใน RESTful แปลว่าอะไร

REST + -ful

เหมือน hopeful = เต็มไปด้วยความหวัง · careful = เต็มไปด้วยความระวัง

RESTful = "ทำตามหลักการ REST"

API ที่ใช้ HTTP และส่ง JSON — เรียกว่า RESTful ได้เลยไหม

ความเข้าใจผิดที่พบบ่อยที่สุด — "ใช้ HTTP + JSON = REST" · ไม่ใช่ · POST /doEverything ที่ส่ง JSON ก็ใช้ HTTP+JSON แต่ไม่ RESTful เลย

API · บท 7 รู้ไว้เพื่อเลือกเป็น

ไม่ได้มีแค่ REST

รูปแบบยุคจุดเด่นจุดอ่อน
SOAP1998เข้มงวด มีมาตรฐานชัด · ธนาคารยังใช้XML เทอะทะ เขียนยาก
REST2000เรียบง่าย ใช้ HTTP ตรง ๆ · คนรู้จักมากที่สุดบางทีต้องยิงหลายครั้งกว่าจะได้ข้อมูลครบ

ทำไมวิชานี้เลือก REST — ① ใช้ HTTP ที่เรียนมาแล้วตรง ๆ ไม่ต้องเรียนอะไรใหม่ · ② เป็นมาตรฐานที่ใช้มากที่สุดในตลาดงาน · ③ เข้าใจ REST แล้วไปเรียน GraphQL ทีหลังง่าย แต่กลับกันไม่ได้

API · CLOSE สรุป

5 ข้อที่ควรจำจากบทนี้

  1. API = ช่องทางที่โปรแกรมเรียกใช้กัน — ไม่ได้แปลว่าเว็บเซิร์ฟเวอร์
  2. มี API เพราะต้องแยกข้อมูลออกจากหน้าตา — client หลายแบบใช้ชุดเดียวกันได้
  3. REST เป็นรูปแบบสถาปัตยกรรม ที่ Roy Fielding เสนอปี 2000 — ไม่ใช่ของที่ติดตั้งได้
  4. RESTful = ทำตามหลักการ REST — และมีระดับ · งานจริงส่วนใหญ่อยู่ Level 2
  5. คิดเป็นทรัพยากร ไม่ใช่การกระทำ — path เป็นคำนาม การกระทำอยู่ที่ method

ทีนี้พร้อมแล้ว — คุณรู้แล้วว่ากำลังสร้างอะไร เพื่ออะไร และทำไมต้องเป็นรูปแบบนี้
ต่อไปคือลงมือสร้าง API ตัวแรกด้วย Node.js และ Express
