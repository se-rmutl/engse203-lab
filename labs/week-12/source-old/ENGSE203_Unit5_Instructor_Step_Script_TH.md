### 11.2 ให้เขียน test ค่าขอบเอง

ไม่มี test ให้ — **ใช้ทักษะเมื่อเช้า** 100 ผ่าน · 101 ไม่ผ่าน · ชวนเขียน helper `checkText` เดียวแทนเขียนซ้ำ 3 ช่อง

### 11.3 ย้ำ validation ≠ sanitize

`<script>` ยังบันทึกได้ — React escape ตอนแสดงผลให้ · **อย่าใช้ `dangerouslySetInnerHTML`** · ไม่ต้องลงลึกเรื่อง XSS

## 12. ช่วง E2 · CP49 scrypt test-first (13:35–14:10)

### 12.1 เล่าเรื่องฐานข้อมูลหลุด

> *"ถ้าวันหนึ่งไฟล์ campus.db หลุดออกไป — คนที่ได้ไฟล์จะได้อะไร"*

ไล่ตาราง plaintext → sha256 (เร็วเกิน) → scrypt + salt · ใช้สไลด์ 15 (รหัสเดียวกัน hash ต่างกัน)

### 12.2 ⭐ test-first ครั้งแรกของวิชา

> *"เมื่อเช้าเราเขียนโค้ดก่อนแล้วเขียน test ตาม — บ่ายนี้กลับกัน test มาแล้ว 10 ข้อ หน้าที่เราคือทำให้มันเขียว"*

เปิด `test:watch -- password` ไว้ · I do `hashPassword` บนจอ · We do `verifyPassword` ทีละขั้นตาม TODO

### 12.3 กับดักที่จะเจอแน่

- test ข้อ "ตรวจ hash ใน schema.sql" ไม่ผ่านข้อเดียว → แปลง salt เป็น Buffer (ทั้งตอน hash และ verify) · **ใช้ข้อความ hex ตรง ๆ** · ถ้า "รหัสผ่านถูก → true" แดงด้วย = แปลงแค่ตอน verify
- ถาม *"ทำไม timingSafeEqual ไม่ใช่ ==="* → ตอบสั้น ๆ: `===` หยุดทันทีที่เจอตัวไม่ตรง เวลาที่ใช้บอกใบ้ว่าตรงกี่ตัว · ไม่ต้องลงลึก

> ไม่ใช้ bcrypt — native module พังบน Windows บ่อย · scrypt มากับ Node ไม่ต้องติดตั้ง (ถ้าใครถาม)

## 13. ช่วง E3 · CP50 login ออก JWT (14:20–14:55)

### 13.1 ⭐ interactive "JWT decoder" (สไลด์ 21)

login ด้วย curl บนจอ → ถอด payload ด้วย `node -pe` (หน้าจอ CP50 ข้อ ④) → **ห้องเห็น payload ทันที** · แล้วเปิดสไลด์ 21 กดปุ่ม token ของ staff → "แก้ role เป็น staff" (decoder ในสไลด์ใช้ token ตัวอย่าง วาง token เองไม่ได้)

> *"ไม่ได้เข้ารหัส แค่ base64 — ใครก็อ่านได้ · แต่ลองแก้ role ดู signature จะไม่ตรง"*

ห้ามใส่รหัสผ่านใน payload — ถามทั้งห้องว่า *"ถ้าใส่ จะเกิดอะไร"* (quiz สไลด์ 22)

### 13.2 ข้อความ error เดียวกัน

ถาม *"อีเมลไม่มี กับ รหัสผิด ทำไมต้องตอบเหมือนกัน"* → ไม่งั้นลองอีเมลไปเรื่อย ๆ ก็รู้ว่าใครมีบัญชี (สไลด์ 20 · กล่องใต้ภาพ)

### 13.3 อย่าลืมผูก route

ข้อผิดพลาดอันดับ 1 คือเขียน `login()` เสร็จแต่ลืม `app.use('/api/auth', authRoutes)` → 404 · ถามกลับ *"route นี้ผูกกับ app หรือยัง"*

## 14. ช่วง E4 · CP51 authenticate + requireRole (14:55–15:30)

### 14.1 interactive "ด่านตรวจ 401/403" (สไลด์ 27)

ลองทั้ง 4 กรณี: ไม่มี token · token ปลอม · requester · staff → ให้เห็นว่าตกด่านไหน ได้ status อะไร

### 14.2 ⭐ moment ของบ่าย — test เมื่อเช้าพัง

ผูก middleware ที่ PUT/DELETE แล้ว `npm test` → test ที่เขียนเมื่อเช้าพัง 6 ข้อ **`expected 401 to be 200`** (ได้ 401 แต่คาด 200)

> *"เมื่อเช้าเราเขียน test ให้ PUT ได้ 200 — ตอนนี้ requirement เปลี่ยน PUT ต้อง login · test ที่พังไม่ใช่ปัญหา มันคือรายการที่บอกว่าต้องแก้ตรงไหนบ้าง"*

(สไลด์ 29) สาธิตแก้ 1 ข้อด้วย `loginAsStaff` · ที่เหลือทำเอง

### 14.3 ห้ามใส่ authenticate ทั้ง router

ถ้าใครได้ 401 แม้แต่ GET → ใส่ `router.use(authenticate)` · ย้ำกติกา **GET/POST เปิด · PUT/DELETE ต้อง login**
