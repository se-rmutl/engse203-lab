1.1 คุณภาพซอฟต์แวร์ — ถูกต้องในทุกกรณีที่ผู้ใช้จะเจอ

ตอน dev เรามักลองแค่ "กรณีปกติ" — กรอกข้อมูลครบ กดส่ง ข้อมูลขึ้น ก็ถือว่าเสร็จ · แต่ผู้ใช้จริงทำสิ่งที่เราไม่ได้ลอง: ลบรายการกลาง เปิดหน้าจอค้างไว้แล้วกดทีหลัง พิมพ์ข้อความยาวพอดีขอบ · คุณภาพจึงหมายถึงระบบทำงานถูกตามที่ตกลงไว้ ในทุกกรณีที่ผู้ใช้จะเจอ ไม่ใช่แค่กรณีที่เราลองตอนเขียน

Bug · อาการ (symptom) · สาเหตุ (root cause)

bug = พฤติกรรมของโปรแกรมที่ต่างจากที่ควรเป็น · อาการคือสิ่งที่ผู้ใช้เห็น (ได้ 500, ตัวเลขเป็น 0) · สาเหตุคือบรรทัดโค้ดที่ทำให้เกิด — ผู้ใช้บอกได้แค่อาการ งานของเราคือหาสาเหตุ

4.1 ทำไมต้องแยก validateRequestInput ออกจาก middleware

ใน W06–07 กฎตรวจข้อมูลอยู่ใน middleware validateRequest(req, res, next) · starter สัปดาห์นี้แยกกฎออกมาเป็น pure function ไว้ที่ validators/requestValidator.js แล้ว middleware เหลือแค่เรียกใช้

// api/src/middleware/validateRequest.js — middleware บาง ๆ
import { validateRequestInput } from '../validators/requestValidator.js';

export function validateRequest(req, res, next) {
  const errors = validateRequestInput(req.body);
  if (errors.length > 0) {
    return res.status(400).json({ error: 'ข้อมูลคำร้องไม่ถูกต้อง', details: errors });
  }
  next();
}

หลักเดียวกับที่ใช้มาตลอดวิชา — แยกหน้าที่ให้ชัด แล้วแต่ละส่วนจะเปลี่ยนหรือทดสอบได้โดยไม่กระทบส่วนอื่น · ฝั่ง frontend ก็ทำแบบเดียวกัน: utils/requestSummary.js แยกการนับออกจาก component SummaryPanel
