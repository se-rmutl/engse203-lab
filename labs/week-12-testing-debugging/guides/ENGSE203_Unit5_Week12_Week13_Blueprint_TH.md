## 2. การตัดสินใจหลัก

### 2.1 สอนวันเดียว แต่บ่ายไม่พึ่งเช้า

| ปัญหา | ทางแก้ |
|---|---|
| ใครทำเช้าไม่เสร็จ บ่ายจะตามไม่ทัน | starter ของบ่าย = **เฉลยของเช้า** · ทุกคนเริ่มบ่ายเท่ากัน |
| สองสัปดาห์ในวันเดียว เนื้อหาปนกัน | แยกโฟลเดอร์ · เอกสาร · สไลด์ · checker เป็นของแต่ละสัปดาห์ |

### 2.2 เช้า: ทุกคนเริ่มจาก codebase ที่มี bug จริง

ไม่ใช้งาน Week 11 ของตัวเอง — เพราะต้องการให้**ทุกคนเจอ bug ชุดเดียวกัน** และอภิปรายร่วมกันได้

ฝัง bug 4 ตัว แต่ละตัว**ต้องใช้เครื่องมือต่างกัน**จึงจะหาเจอ

| bug | ผู้ใช้แจ้งไหม | เครื่องมือที่ทำให้เจอ |
|---|---|---|
| #0 | ไม่ | unit test ค่าขอบ |
| #1 | แจ้ง | breakpoint (เกิดตามลำดับการกระทำ) |
| #2 | แจ้ง | DevTools Network (แยกว่าเป็น frontend หรือ API) |
| #3 | แจ้ง | stack trace |

> **test ที่มีอยู่ใน starter ผ่านทั้งหมด** ทั้งที่มี bug — นี่คือจุดเริ่มของการเรียน ไม่ใช่ข้อบกพร่องของ starter

### 2.3 Vitest แทน node:test

| เหตุผล | |
|---|---|
| ใช้ได้ทั้ง api และ frontend (React) ด้วยเครื่องมือเดียว | ตรง มคอ. "Jest/Vitest" |
| watch mode · coverage ในตัว | ให้วงจร เขียน → เห็นผล สั้นที่สุด |
| ใช้ **Vitest 5** | รุ่นเก่า (ที่ใช้ Vite 5) ตัด `node:` ออกจาก `node:sqlite` แล้วพัง |

นักศึกษาเคยเขียน test ด้วย node:test แล้ว (W07, W10) → **ไม่สอน syntax เป็นเรื่องใหม่** เน้นการออกแบบ test case

### 2.4 บ่าย: กติกาสิทธิ์ที่เรียบง่ายที่สุด

| ทำอะไร | ใครทำได้ |
|---|---|
| GET · POST | ทุกคน (ระบบรับเรื่อง — ผู้แจ้งไม่ต้องมีบัญชี) |
| PUT · DELETE | เจ้าหน้าที่เท่านั้น |

มีบทบาทเดียวที่ต้อง login (`staff`) → สอน 401 vs 403 ได้ครบโดยไม่ต้องมีระบบสมัครสมาชิก

### 2.5 scrypt แทน bcrypt

`scrypt` มากับ Node (`node:crypto`) ไม่ต้องติดตั้ง · bcrypt เป็น native module ที่ติดตั้งบน Windows แล้วพังบ่อย

### 2.6 test-first ใน CP49

ให้ `password.test.js` มาก่อน 10 ข้อ — นักศึกษาเห็นครั้งแรกว่า **test เป็นสเปก** ไม่ใช่แค่สิ่งที่เขียนตามหลังโค้ด

### 2.7 ให้ test เดิมพังโดยตั้งใจ (CP51)

ผูก middleware แล้ว test PUT/DELETE ของเมื่อเช้าพัง 401 → บทเรียน *"requirement เปลี่ยน test ต้องเปลี่ยนตาม"* · ให้ helper `loginAsStaff` / `tokenFor` มาเพื่อไม่ให้เสียเวลากับ boilerplate

### 2.8 ไม่มีงาน take-home แยก

งานต่อจากคาบ (หน้า login ฝั่ง React · test เพิ่ม · Release Checklist · deploy) **เป็นข้อกำหนดของ Final Term Project** — เพราะสัปดาห์ 14–16 ไม่มีคาบเรียนแล้ว และงานเหล่านี้เป็นงานจริงของแต่ละบทบาทในทีม

## 4. Checker

| | สัปดาห์ 12 | สัปดาห์ 13 |
|---|---|---|
| ไฟล์ | `check-week12.mjs` | `check-week13.mjs` |

| รวม | 22 | 27 |
| starter | 6/20 | 5/23 |
| เฉลย | 22/22 | 27/27 |

หลักการออกแบบ checker

- **รัน Vitest ของโปรเจกต์จริง** — ไม่เขียน test ซ้ำใน checker
- **ฐานข้อมูล `:memory:` เสมอ** — ไม่แตะ `campus.db` หรือ Turso ของนักศึกษา
- **ตัวหารคงที่** — ไม่ว่าโค้ดจะพังแค่ไหน จำนวนข้อเท่าเดิม (ข้อที่รันไม่ได้นับว่าไม่ผ่านพร้อมเหตุผล)
- **check-week12 รู้จัก auth** — ถ้ามี `/api/auth/login` จะ login เอง จึงใช้ซ้ำในโฟลเดอร์ W13 ได้ (ตรวจว่าไม่ถอยหลัง)
- checker สัปดาห์ 7 และ 10 ไม่อยู่ในโฟลเดอร์ W13 — requirement เปลี่ยนแล้ว
